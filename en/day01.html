    Day 1 · What is an AI Agent? Start with the learning map¶

    Day 1 / 30 · about 40 min · Sources: README · ROADMAP · For everyone

    No code today. Two goals: know what an agent is and where the next 30 days will take you, then meet two agent tools you can use to save time right away: Claude Code and Codex.

    Today's mind map¶

    Click a branch to jump to its section

    1. What exactly is an AI agent?¶

    Definition

    An AI agent is "an AI system that, for a person's goal, decides the next step by itself and takes action."

    Once you give it a goal, it repeats these steps:

    Read the situation→Choose the next step→Use tools when needed→Check the result→Continue / fix / stop / hand back

    It can finish work for you automatically, but only within the rules and permissions you give it.

    Think of it as an intern who can get things done on their own

    You say, "Book me a train to Shanghai next Wednesday." A plain chatbot only tells you how to book. An agent checks your calendar, searches trains, picks a good time, and asks before paying: "Confirm the 8:00 G7 train?"

    What is not necessarily an agent:

    Type Why it doesn't count
    A chatbot that answers one question at a time It doesn't choose its next step, use tools, or adjust based on results
    A script where every step is hard-coded No judgment; it won't change course when something unexpected happens

    2. Three steps to learn¶

    You don't need to know every term up front. The map takes you through three things in order:

    • Learn the basics

      What an LLM (a model that reads and writes language), a prompt, an API (an interface programs use to call a service), and a token are

    • Build something

      Let the model call tools, run an agent loop, read files, and remember things

    • Make it reliable

      Add permissions, evals, human approval, observability, and failure recovery

    3. The map: 10 stations, two main tracks¶

    The whole map has 8 topic stages + a Stage 0 prep station + a Stage 7.5 advanced reading station, 10 stations in total.

    Shared basics (everyone starts here)¶

    Stage What it answers What you can do after
    0 Foundations Are your computer and basic tools ready? Call a public API with Python, read JSON, save work with Git
    1 LLM basics How LLMs, tokens, context, and models differ Call an LLM and choose a cloud or local model for the job
    2 Prompt design How to state goals, data, rules, and output clearly Compare the limits of zero-shot, few-shot, and CoT

    If you already know Python, Git, and APIs, you can skip Stage 0.

    Then pick a main track¶

    For: people who want to get work done with existing tools like Claude Code and Codex

    Order: A1 → A2 → Stage 5 → A3 → Stage 8　Time: about 8–10 weeks

    For: people who want to write their own agents, tool loops, workflows, and services

    Order: Stage 3 → 4 → 5 → 6 → 7 → 7.5 → 8　Time: about 16–22 weeks for the core

    For: people who won't code for now and just want to use AI safely

    Order: go straight to the role guide and read as needed

    Both tracks pass through Stage 5 (the Claude Code ecosystem) and Stage 8 (agent interfaces): Track A learns how to use them, Track B learns how to build them into its own agent.

    Continue by role: 5 role paths¶

    Researchers · Developers · Teachers · Knowledge workers · Everyday users. Read what fits; you don't need all of them.

    4. Key terms today¶

    • LLM · Large Language Model

      The "brain" that reads and writes language, such as Claude, GPT, or DeepSeek.

    • Prompt

      The instructions and material you give the model, like a task brief for an employee.

    • Token

      The smallest unit a model reads and writes; pricing and length limits are counted in tokens.

    • API · Application Programming Interface

      The "socket" a program uses to call a service; agents use it to call models and tools.

    • Tool

      What lets an agent act: search, read files, send messages, check the weather…

    • Agent Loop

      The repeating "think → act → check → think again" cycle; it needs a maximum turn count so it can't run forever.

    • Eval · Evaluation

      A fixed set of test cases that checks whether the agent is right, so you spot regressions right after a change.

    • HITL · Human-in-the-loop

      Human approval: key actions (paying, deleting, sending externally) need a person to confirm first.

    Forgot a term? Check the glossary any time.

    5. How to avoid getting stuck¶

    1. One stage at a time: answer the chapter's core question first.
    2. Key terms and required reading first: you'll use them directly in later exercises.
    3. Copy the first command as is: get it running instead of starting from a blank file.
    4. Change one thing at a time: test right after each change so you know what caused the result.
    5. Meet the done-check before moving on: understanding is not the same as being able to do it.

    6. Hands-on · Meet Claude Code and Codex¶

    The easiest agents to start with are two ready-made tools: Claude Code (by Anthropic) and Codex (by OpenAI). They don't just chat: they can read files on your computer, edit them, and run commands to carry a task from start to finish. "Code" is in the name, but plenty of everyday office work fits too.

    What they can do for you¶

    Task at work Before With the tool
    Merge dozens of Excel / CSV files in a folder, dedupe, unify formats Copy and paste by hand, half a day Describe what you need; it writes the steps and produces the result file
    Read a long requirements doc or contract and pull out key points and risks Page by page, 1–2 hours Point it at the file, get a summary in minutes, then check the key parts yourself
    Draft a weekly report, meeting minutes, or an email Start from a blank page Give it the material and format, get a draft, then edit
    Turn sales data into charts and conclusions Pivot tables and charts by hand It analyzes, charts, writes conclusions, and tells you the method it used
    Repetitive daily clean-up Do it by hand every day Have it write a small script or scheduled task that runs on its own

    What it's not good at, and where you must check

    • Verify facts and numbers: it can misread or miscalculate. Always check key conclusions against the source.
    • It doesn't make decisions for you: it proposes; you approve anything final, external, financial, or destructive.
    • Mind company data: only give it files you're allowed to process with AI tools; check company rules before using sensitive customer data.

    Where to use them¶

    • Desktop app: install the Claude desktop app and open the Code tab. Best for non-programmers: a visual interface that shows exactly which files it changed.
    • Terminal: the most complete version. Install in Windows PowerShell with irm https://claude.ai/install.ps1 | iex, go to your work folder, and run claude.
    • VS Code / JetBrains plugins: use it inside your editor.
    • Web at claude.ai/code: no install; good for projects hosted on GitHub.

    Requires a Claude subscription or an Anthropic account.

    • ChatGPT desktop app / web / mobile: use Codex directly inside ChatGPT.
    • Codex CLI: run codex in a project folder and choose Sign in with ChatGPT the first time.
    • IDE extension, Codex Cloud: use it in your editor, or hand tasks off to run in the cloud.

    Requires a paid ChatGPT plan such as Plus, Pro, Business, Enterprise, or Edu.

    Which one to pick¶

    Situation Suggestion
    Your company already provides one of them Start there. Their abilities are close; practice matters more than the choice of tool
    You're not comfortable with the command line Start with a desktop app (the Code tab in Claude's desktop app, or Codex in the ChatGPT desktop app)
    You want every feature and batch automation Use the command-line versions (claude / codex)
    Not sure Try the same small task in both and keep the one that feels right

    Three rules for your first time¶

    1. Start it in a dedicated work folder, and practice on copies of your files, not the originals.

    2. Be specific about the task: say which file, what result, and what counts as done.

      Instead of Try
      "Tidy up the data" "Merge every CSV in the sales/ folder into one table, sort by date, remove duplicate order IDs, save it as summary.xlsx, then tell me how many rows were merged and how many duplicates were removed"

    3. Ask for evidence: when it's done, have it explain what it did and how it checked, then spot-check the result. If it drifts, press Esc to interrupt and restate the task.

    Your first prompt today¶

    Open Claude Code or Codex in a folder with a few work documents and type:

    Look through the files in this folder and tell me:
1. Roughly what each file contains (one sentence each)
2. Which repetitive tasks you think you could take over
Don't change any files yet.

    Today's exercises (with answers)¶

    Exercise 1 · Which of these are agents?¶

    • A. A support bot: you ask for opening hours and it replies "9:00–18:00."
    • B. A script that emails a fixed-format sales report every day at 8:00.
    • C. You say "Turn this week's meetings into minutes and post them to the group," and it reads your calendar, finds the meeting notes, writes the minutes, and asks you before sending.
    • D. Our Feishu study assistant: it sends lessons every day and, when you ask a question, looks up the material before answering.
    Show answer

    C and D are agents; A and B are not.

    • A: one question, one answer. It doesn't choose its next step or use tools; it's a plain chatbot.
    • B: every step is hard-coded and needs no judgment; it's a fixed script (automation ≠ agent).
    • C: it has a goal, picks its own steps, uses several tools, checks results, and hands back to you before a key action. A textbook agent.
    • D: when answering, it decides which material to look up (a tool) and answers from the result, so it's an agent. Note that its daily push is triggered on a schedule, and the trigger itself is fixed.

    Exercise 2 · Sort these into the three steps¶

    Token, letting the model call a weather tool, human approval, prompt, reading files, eval, agent loop, failure recovery

    Show answer
    • Learn the basics: token, prompt
    • Build something: letting the model call a weather tool, reading files, agent loop
    • Make it reliable: human approval, eval, failure recovery

    Exercise 3 · Pick a track for each colleague¶

    1. Wang is a product manager who wants AI tools to organize requirement docs and write weekly reports, with no plans to code.
    2. Li is a backend engineer who wants to build an agent service that looks up orders and handles refund requests automatically.
    3. Zhang works in operations, writes copy with AI, and worries that pasting in customer information isn't safe.
    Show answer
    • Wang → Track A (CLI Power User), or start with the knowledge-worker role path. He wants to get work done with existing tools.
    • Li → Track B (Agent Builder). He has to write tool loops and a service, and refunds involve money, so Stage 7's permissions, human approval, and recovery are a must.
    • Zhang → the everyday-user path. The focus is privacy and safe use; no coding needed for now.

    All three should go through the core ideas of Stage 0–2 first (optional for Zhang).

    Exercise 4 · Hands-on: which tasks suit Claude Code / Codex?¶

    • A. Turn 30 meeting transcripts into minutes with one consistent format
    • B. Decide how to split next quarter's budget
    • C. Every Monday, export last week's ticket data, compute stats, and chart it
    • D. Send a client a formal email that involves contract amounts
    Show answer
    • A and C fit well: repetitive, patterned, and easy to check. C can even become a task that runs automatically every week.
    • B shouldn't be handed over directly: it's a decision you own. Let it gather past data and lay out options with pros and cons, but you make the call.
    • D: let it draft, but you must review and send it: it involves money and external communication, which is exactly where human approval is required.

    Think about it · "Make it reliable" comes last, so why can't you skip it?¶

    Show answer

    Because an agent acts, it doesn't just talk. When a chatbot gives a wrong answer, a person notices at a glance. When an agent takes a wrong step, the email may already be sent, the file deleted, the money paid.

    That's why you add permissions (only the abilities it needs), human approval (confirm key actions first), evals (know right away if a change made things worse), observability (see which step failed), and failure recovery (stop or roll back safely). It comes last because you need something that runs before you can make it reliable, but you can't skip any of it before going live.
