    第 1 天 · AI Agent 是什么？先看懂这张学习地图¶

    第 1 天 / 30 · 约 40 分钟 · 资料：README · ROADMAP · 适合所有人

    今天不写代码，做两件事：知道 Agent 是什么、接下来 30 天往哪里走，再认识两件马上能用来提效的 Agent 工具：Claude Code 和 Codex。

    今日学习导图¶

    点击分支跳到对应章节

    1. AI Agent 到底是什么¶

    定义

    AI Agent（AI 智能体）是“能为了人的目标，自己判断下一步并采取行动的 AI 系统”。

    人给它一个目标后，它会反复做这几件事：

    读取当前情况→选择下一步→需要时使用工具→看结果→继续 / 修正 / 停止 / 交还给人

    它可以自动替人完成工作，但只能在人给的规则和权限内行动。

    生活化理解：Agent 像一个“能独立办事的实习生”

    你说“帮我订下周三去上海的高铁”。普通聊天机器人只会告诉你怎么订票。Agent 会自己查日历、搜车次、挑合适的时间，付款前再问你一句“确认购买 G7 次 8:00 这班吗？”

    什么不一定是 Agent：

    类型 为什么不算
    问一次答一次的聊天机器人 不会自己决定下一步、不用工具、不看结果再调整
    每一步都写死的脚本 没有“判断”，遇到意外情况不会改变做法

    2. 学习三步走¶

    这份地图不要求你一开始就懂所有名词，而是按顺序带你完成三件事：

    • 先懂基础

      LLM（能读写语言的模型）、Prompt、API（让程序调用服务的接口）与 Token 是什么

    • 再做出东西

      让模型调用工具、跑 Agent Loop、读文件与记住事情

    • 最后做得可靠

      加入权限、Eval、人工批准、观测与失败恢复

    3. 地图结构：10 个学习站，两条主路线¶

    整张地图有 8 个主题 Stage + Stage 0 准备关 + Stage 7.5 进阶阅读站，共 10 个学习站。

    共用基础（所有人先走）¶

    Stage 解决什么问题 完成后你能做什么
    0 基础准备 电脑与基本工具准备好了吗？ 用 Python 调用公开 API、读 JSON，用 Git 保存成果
    1 LLM 基础 LLM、Token、Context 与模型的区别 调用一个 LLM，按需求选云端或本机模型
    2 Prompt 设计 怎么把目标、数据、规则、输出说清楚 比较 Zero-Shot、Few-Shot 与 CoT 的边界

    已经会 Python、Git 与 API 的人可以跳过 Stage 0。

    然后选一条主路线¶

    适合：想用 Claude Code、Codex 等现成工具把工作做完的人

    顺序：A1 → A2 → Stage 5 → A3 → Stage 8　时间参考：约 8–10 周

    适合：想自己写 Agent、工具循环、Workflow 与服务的人

    顺序：Stage 3 → 4 → 5 → 6 → 7 → 7.5 → 8　时间参考：主干约 16–22 周

    适合：暂时不写程序，只想安全使用 AI 的人

    顺序：直接看角色指南，按需阅读

    两条路线都会经过 Stage 5（Claude Code 生态） 和 Stage 8（Agent 操作界面）：Track A 学“怎么用”，Track B 学“怎么组合进自己的 Agent”。

    按身份继续走：5 条角色路线¶

    研究人员 · 开发者 · 教师 · 知识工作者 · 日常用户。按需选读，不必全部走完。

    4. 今天出现的核心名词¶

    • LLM · Large Language Model

      大语言模型，能读、能写语言的“大脑”，比如 Claude、GPT、DeepSeek。

    • Prompt · 提示词

      你给模型的指令和资料，相当于给员工的任务说明。

    • Token · 词元

      模型读写文字的最小单位，计费和长度限制都按它算。

    • API · 应用程序接口

      让程序去调用某个服务的“插座”，Agent 用它调用模型和工具。

    • Tool · 工具

      Agent 能“动手”的能力：搜索、读文件、发消息、查天气……

    • Agent Loop · 智能体循环

      “想 → 做 → 看结果 → 再想”的重复过程，要设最大轮数防止停不下来。

    • Eval · 评测

      用一组固定案例检查 Agent 做得对不对，改动后能马上发现退步。

    • HITL · Human-in-the-loop

      人工批准：关键操作（付款、删除、对外发送）先让人确认。

    忘了某个词，随时查核心名词表。

    5. 怎么学才不容易卡住¶

    1. 一次只走一个 Stage：先回答这一章的核心问题。
    2. 核心词与必读先看：它们会直接用在后面的练习。
    3. 直接复制第一个命令：先跑起来，不必从空白文件开始。
    4. 一次只改一件事：改完立刻测试，才知道是哪个改动造成的结果。
    5. 做到完成条件再往下走：看懂不等于做得到。

    6. 实操 · 认识 Claude Code 与 Codex¶

    前面讲的“Agent”，最容易上手的就是这两件现成工具：Claude Code（Anthropic 出品）和 Codex（OpenAI 出品）。它们不只是会聊天，而是能直接读你电脑上的文件、改文件、运行命令，把一件事从头做到尾。名字里带“Code”，但很多日常办公也能用。

    它们能帮你做什么¶

    工作中的事 以前怎么做 交给它之后
    把文件夹里几十个 Excel / CSV 合并、去重、统一格式 手动复制粘贴，半天 说一句需求，它写好处理步骤并直接生成结果文件
    读一份很长的需求文档 / 合同，整理要点和风险 逐页读，1–2 小时 指定文件让它读，几分钟出摘要，你再核对重点
    写周报、会议纪要、邮件初稿 从空白开始写 给它素材和格式，出初稿，你来改
    从销售数据里出图表和结论 手动做透视表、画图 它分析数据、画图、写结论，并告诉你用了什么方法
    每天重复的整理工作 每天手动做一遍 让它写成一个小脚本或定时任务，以后自动跑

    它不擅长、需要你把关的

    • 事实和数字要核对：它可能读错、算错，关键结论一定要自己看一遍原文。
    • 不能代替你做决定：它给方案，最终拍板、对外发送、付款、删除，都由你来。
    • 公司数据注意保密：只给它处理允许使用 AI 工具的文件，敏感客户信息先确认公司规定。

    在哪里用：几个入口¶

    • 桌面 App：安装 Claude 桌面版，点 Code 标签页。最适合非程序员，有图形界面，能直接看到它改了哪些文件。
    • 终端（命令行）：功能最全。Windows PowerShell 安装：irm https://claude.ai/install.ps1 | iex，然后进入工作文件夹，输入 claude 启动。
    • VS Code / JetBrains 插件：在编辑器里用。
    • 网页版 claude.ai/code：不用安装，适合处理放在 GitHub 上的项目。

    需要 Claude 订阅或 Anthropic 账号。

    • ChatGPT 桌面 App / 网页 / 手机：在 ChatGPT 里直接使用 Codex。
    • Codex CLI（命令行）：在项目文件夹里输入 codex 启动，首次选择 Sign in with ChatGPT 登录。
    • IDE 插件、Codex Cloud：在编辑器里用，或把任务交到云端跑。

    需要 ChatGPT 的 Plus / Pro / Business / Enterprise / Edu 等付费方案。

    怎么选¶

    情况 建议
    公司已经给了某一家的账号或网关 先用那一家，两者能力接近，熟练度比工具选择更重要
    不熟悉命令行 从桌面 App 开始（Claude 桌面版的 Code 标签页，或 ChatGPT 桌面版里的 Codex）
    想要最全的功能、批量自动化 用命令行版本（claude / codex）
    拿不准 同一个小任务两边都试一次，选顺手的那个

    第一次用记住这三条¶

    1. 在一个专门的工作文件夹里启动，先复制一份文件进去练手，别直接动原件。

    2. 把任务说具体：写清楚“用哪个文件、要什么结果、什么算完成”。

      不要这样说 要这样说
      “帮我整理一下数据” “把 销售/ 文件夹里所有 CSV 合并成一个表，按日期排序，删除重复订单号，输出 汇总.xlsx，最后告诉我合并了多少行、删了多少条重复”

    3. 让它给证据：做完后让它说明“做了什么、怎么验证的”，你再抽查结果。跑偏了就按 Esc 打断，重新说清楚。

    今天可以试的第一句话¶

    打开 Claude Code 或 Codex，在一个放了几份工作文档的文件夹里，输入：

    请浏览这个文件夹里的文件，告诉我：
1. 每个文件大概是什么内容（每个一句话）
2. 你觉得哪些重复性工作可以交给你来做
先不要修改任何文件。

    今日练习（附参考答案）¶

    练习 1 · 判断：下面哪些是 Agent？¶

    • A. 客服机器人：你问“营业时间”，它回答“9:00–18:00”。
    • B. 每天 8 点把固定格式的销售报表发到邮箱的脚本。
    • C. 你说“把本周会议整理成纪要发到群里”，它自己读日历、找会议记录、写纪要，发送前请你确认。
    • D. 我们的飞书学习助手：每天推送学习内容，你提问时先查资料再回答。
    查看参考答案

    C 和 D 是 Agent；A 和 B 不是。

    • A：一问一答，不会自己决定下一步、不用工具，是普通聊天机器人。
    • B：每一步都写死，不需要判断，是固定脚本（自动化 ≠ Agent）。
    • C：有目标，自己选步骤、用多个工具、看结果，关键操作前交还给人确认，是标准的 Agent。
    • D：回答问题时会自己决定查哪份资料（用工具），再根据结果作答，属于 Agent。注意它的“每天推送”是定时触发的，触发方式本身是固定的。

    练习 2 · 分类：把下列内容放进“学习三步”中的哪一步？¶

    Token、让模型调用天气工具、人工批准、Prompt、读取文件、Eval、Agent Loop、失败恢复

    查看参考答案
    • 先懂基础：Token、Prompt
    • 再做出东西：让模型调用天气工具、读取文件、Agent Loop
    • 最后做得可靠：人工批准、Eval、失败恢复

    练习 3 · 选路线：这三位同事分别该走哪条路线？¶

    1. 小王是产品经理，想用 AI 工具帮自己整理需求文档、写周报，不打算写代码。
    2. 小李是后端工程师，想给公司做一个能查订单、自动处理退款申请的 Agent 服务。
    3. 小张是运营，平时用 AI 写文案，担心把客户信息贴进去不安全。
    查看参考答案
    • 小王 → Track A（CLI Power User），或者先看“知识工作者”角色路线。他要的是用好现成工具完成工作。
    • 小李 → Track B（Agent Builder）。要自己写工具循环和服务，而且退款涉及资金，Stage 7 的权限、人工批准、恢复一定要学。
    • 小张 → 日常用户路线。重点是隐私与安全使用，暂时不需要写程序。

    三人都建议先过一遍 Stage 0–2 的核心概念（小张可按需）。

    练习 4 · 实操：哪些工作适合交给 Claude Code / Codex？¶

    • A. 把 30 份会议录音转写稿整理成统一格式的纪要
    • B. 决定下季度预算怎么分配
    • C. 每周一把上周的工单数据导出、统计、做成图表
    • D. 给客户发一封涉及合同金额的正式邮件
    查看参考答案
    • A、C 很适合：重复、有规律、结果容易检查。C 还可以做成每周自动跑的任务。
    • B 不适合直接交给它：这是需要你负责的决策。可以让它先整理历史数据、列出几种方案和利弊，但拍板的是你。
    • D 可以让它写初稿，但必须你来审核和发送：涉及金额和对外沟通，属于“关键操作要人工批准”。

    思考题 · “做得可靠”放在最后一步，为什么不能省？¶

    查看参考答案

    因为 Agent 会自己行动，不只是说话。聊天机器人答错一句话，人看一眼就能发现；Agent 做错一步，可能已经把邮件发出去、把文件删了、把钱付了。

    所以要加上：权限（只给必要的能力）、人工批准（关键操作先确认）、Eval（改动后马上知道有没有变差）、观测（出错时看得见是哪一步）、失败恢复（出错后能安全停下或回滚）。放在最后，是因为要先有能跑的东西才能谈可靠；但上线前一步都不能省。
